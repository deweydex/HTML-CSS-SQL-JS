How they work together

Think of a login page:

  • HTML creates the form: a box for your username, a box for your password, and a button
  • CSS decides how the form looks: its colours, fonts and spacing
  • SQL looks up your username in a database, and checks your password against a hashed (scrambled, one-way) copy of it. Well-built sites never store your actual password.

Part 1: HTML basics

Getting started

Read an example, then try it. Whenever you wonder "what would happen if I changed this?", change it and see. That question is most of how programmers learn.

What is HTML?

HTML (HyperText Markup Language) is the standard language for creating web pages. It uses tags to structure content.

An HTML page

<!DOCTYPE html>
<html>
<head>
    <title>My Page</title>
</head>
<body>
    <h1>Hello World!</h1>
    <p>This is a paragraph.</p>
</body>
</html>

Common HTML tags

  • <h1> to <h6>: headings (h1 is the largest, h6 the smallest)
  • <p>: a paragraph
  • <a href="url">: a link
  • <img src="image.jpg" alt="description">: an image
  • <div>: a container (division) that groups things
  • <span>: a container inside a line of text
  • <ul> and <li>: a bulleted (unordered) list
  • <table>, <tr>, <td>: a table, its rows and its cells

HTML forms

Forms collect information from the person using the page. Try this one:

The HTML for this form

<form>
    <label for="name">Name:</label>
    <input type="text" id="name" name="name" required>
    
    <label for="email">Email:</label>
    <input type="email" id="email" name="email" required>
    
    <label for="age">Age:</label>
    <input type="number" id="age" name="age" min="1" max="120">
    
    <button type="submit">Submit</button>
</form>

Part 2: CSS styling

Getting started

You can change the CSS of any web page, including this one. Right-click something on the page and choose Inspect. The panel that opens is the browser's DevTools (developer tools), and it shows the CSS for whatever you clicked. Click a value, such as a colour, and type a new one. Nothing you change there is saved, so experiment freely: refreshing the page puts everything back.

What is CSS?

CSS (Cascading Style Sheets) controls how HTML elements look on the page: colours, fonts, layouts, and more.

A spelling note: CSS uses American spelling, so the property is color, never colour. If you write colour: red; the browser quietly ignores it. No error, just nothing happens.

Three ways to add CSS

  1. Inline: <p style="color: blue;">Text</p>
  2. Internal: In <style> tags within <head>
  3. External: a separate .css file. This is the usual choice, and the one this page uses.

CSS syntax

selector {
    property: value;
    another-property: value;
}

/* Example: */
p {
    color: blue;
    font-size: 16px;
    margin: 10px;
}

CSS selectors

  • element: every element of that type, for example p
  • .class: every element with that class, for example .highlight
  • #id: the one element with that id, for example #header
  • element.class: both at once, for example p.intro

The box model

Every HTML element is a rectangular box, built in layers from the inside out:

Margin
Border
Padding
Content

CSS exercise 1: Colour and corners

Make the card green, with rounded corners.

Show hint

background-color takes a colour name, like lightgreen, or a hex code, like #c8f7c5. Rounded corners come from border-radius.

Show answer 
.card {
  background-color: lightgreen;
  padding: 10px;
  border: 2px solid green;
  border-radius: 12px;
}

The bigger the border-radius, the rounder the corners. Try 50px.

CSS exercise 2: Room to breathe

Give the card more space inside its border, and more space around the outside of it.

Show hint

Look back at the box model: padding is the space inside the border, margin is the space outside it.

Show answer 
.card {
  background-color: lightyellow;
  padding: 24px;
  margin: 30px;
  border: 2px solid gray;
}

Padding pushes the text away from the border. Margin pushes the whole card away from everything else.

CSS exercise 3: A second rule

Change the heading's colour and font, and centre all the text in the card.

Show hint

Write a second rule whose selector is h2. The properties you need are color, font-family and text-align. Remember: color, not colour!

Show answer 
.card {
  background-color: lightyellow;
  padding: 10px;
  border: 2px solid gray;
  text-align: center;
}

h2 {
  color: darkblue;
  font-family: Georgia, serif;
}

text-align goes on .card because it affects everything inside the card. The h2 rule affects only the heading.

Try it: restyle this page

The Appearance button, at the right-hand end of the bar at the top of the screen, changes how this page looks. Open it, switch to the dark theme, then try a different font or a bigger text size.

The HTML stays exactly the same when you do this. The page keeps its colours and sizes in CSS variables: values with a name, such as --bg for the background colour. The Appearance panel swaps in a different set of values. Here is a small piece of this page's own styles.css:

:root {
    --bg: #f5f7fa;
    --fg: #1f2933;
}

:root[data-theme="dark"] {
    --bg: #12151c;
    --fg: #e6e8eb;
}

body {
    background-color: var(--bg);
    color: var(--fg);
}

Something to notice: the body rule never mentions dark mode. It only asks for var(--bg). Which rule decides what --bg is, and when?

Part 3: SQL database queries

Getting started

Read the commands first, or jump straight to the playground and click an example query. Both work. The database starts fresh every time you refresh the page, so you can't break anything permanently.

Choose your database

Every example and exercise in this part works with the database you pick. You can switch whenever you like: switching starts the database fresh.

What is SQL?

SQL (Structured Query Language) is used to manage and query databases. It lets you store, retrieve, update, and delete data.

The sample database

The shop database has three tables:

  • customer_tbl: one row per customer (customer_id, customer_name, county)
  • product_tbl: one row per thing the shop sells (product_id, product_name, category, price, stock)
  • order_tbl: one row per line on a receipt, saying who bought what, and how many (order_id, order_date, quantity, customer_id, product_id)

Three habits make the database easier to read:

  • Every table's name ends in _tbl, so you can tell a table from a column at a glance.
  • Every table's id is named after the table: the id in product_tbl is product_id.
  • A column that points at another table's id is called a foreign key. Foreign keys always go at the bottom of a table, and they have the same name as the id they point at.
See the SQL that built these tables 
CREATE TABLE customer_tbl (
    customer_id INTEGER PRIMARY KEY AUTOINCREMENT,
    customer_name TEXT NOT NULL,
    county TEXT NOT NULL
);

CREATE TABLE product_tbl (
    product_id INTEGER PRIMARY KEY AUTOINCREMENT,
    product_name TEXT NOT NULL,
    category TEXT NOT NULL,
    price REAL NOT NULL,
    stock INTEGER NOT NULL
);

CREATE TABLE order_tbl (
    order_id INTEGER PRIMARY KEY AUTOINCREMENT,
    order_date TEXT NOT NULL,
    quantity INTEGER NOT NULL,
    customer_id INTEGER NOT NULL,
    product_id INTEGER NOT NULL,
    FOREIGN KEY (customer_id) REFERENCES customer_tbl (customer_id),
    FOREIGN KEY (product_id) REFERENCES product_tbl (product_id)
);

The school database has three tables:

  • student_tbl: one row per student (student_id, student_name, county)
  • module_tbl: one row per module the school teaches (module_id, module_name, department, credits, hours)
  • result_tbl: one row per exam result, saying which student sat which module, and their mark (result_id, exam_date, mark, student_id, module_id)

Basic SQL commands

SELECT: get data

SELECT column1, column2 FROM table_name;

Gets data from a table. Use * to get every column.

WHERE: keep only some rows

SELECT * FROM product_tbl WHERE price < 10;

Keeps only the rows that match a condition. Try it: three of the six products cost less than €10.

ORDER BY: sort the results

SELECT * FROM product_tbl ORDER BY price DESC;

Sorts the results: ASC for ascending (A to Z, small to big), DESC for descending.

INSERT: add rows

INSERT INTO customer_tbl (customer_name, county)
VALUES ('Sam', 'Cork');

Adds a new row to a table.

UPDATE: change rows

UPDATE product_tbl SET stock = 50
WHERE product_name = 'Notebook';

Changes existing rows. Without a WHERE, it changes every row.

DELETE: remove rows

DELETE FROM order_tbl WHERE order_id = 5;

Removes rows. Without a WHERE, it removes every row.

SQL exercise 8: Combining conditions

Find the Stationery and Tech products that cost less than €10, cheapest first.

Show hint

Join conditions with AND and OR. Brackets decide which part is worked out first, just as in maths.

SQL exercise 9: Items, not orders

How many items has the shop sold altogether? Careful: that isn't the same as the number of orders.

Show hint

COUNT(*) counts rows, but one order can be for several of the same thing. SUM(column) adds up every value in a column.

Show answer

SQL exercise 8: Combining conditions

Find the Computing and Business modules with 3 or more teaching hours a week, most hours first.

Connecting tables with JOIN

So far each query has used one table. order_tbl is where the three tables meet: each row is one line on a receipt, saying who bought what, and how many. It doesn't store any names, only ids that point at rows in the other tables:

  • customer_id matches a customer_id in customer_tbl
  • product_id matches a product_id in product_tbl

Because each foreign key has the same name as the id it points at, you can see the links just by reading the column names. The diagram of the database shows the same links as lines. To see names instead of numbers, you JOIN the tables: you tell the database which columns should match, and it puts the matching rows side by side.

Example: each order with the customer's name

SELECT customer_tbl.customer_name, order_tbl.quantity, order_tbl.product_id
FROM order_tbl
JOIN customer_tbl ON customer_tbl.customer_id = order_tbl.customer_id;

Read the ON line as "match each order to the customer with the same customer_id". Writing customer_tbl.customer_id instead of just customer_id says which table the column comes from. Here you have to, because both tables have a column called customer_id.

SQL exercise 13: Left on the shelf (hardest)

Which product has nobody ordered yet?

Show hint

A plain JOIN only keeps rows that match, so a product with no orders disappears. A LEFT JOIN keeps every product and leaves the order columns empty (NULL) where nothing matched. Then keep only the rows where the order is NULL.

Show answer 
SELECT product_tbl.product_name
FROM product_tbl
LEFT JOIN order_tbl ON order_tbl.product_id = product_tbl.product_id
WHERE order_tbl.order_id IS NULL;

The headphones, which makes sense: there are none in stock. If you deleted them in Exercise 7, press Reset Database first. Now try the same idea for customers: who hasn't bought anything? (Wei Chen, and you too if you added yourself.)
